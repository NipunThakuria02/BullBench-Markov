# EXPERIMENT PROTOCOL — BullBench MarkovLab

**Status:** Official-track DRAFT v0.1, NOT FROZEN. The separately authorized exploratory track now has development results and a locked historical test under [EXPLORATORY_PROTOCOL_V1.md](EXPLORATORY_PROTOCOL_V1.md). This does not pass official G0 or freeze this official-only protocol.
**Rule:** Every item marked `TBD` or `PROPOSED` must be decided and recorded in `docs/DECISIONS.md`, then this file is frozen (Section 14) **before** any final-test or prospective prediction is generated. After freezing, changes go in Section 13 (deviation log), never silent edits.

## 1. Research questions
- **Primary (RQ1):** Given information available after session *t*, does a Gaussian HMM give better-calibrated probabilities of a large absolute return in session *t+1* than (a) training prevalence, (b) persistence, (c) observable Markov chain, (d) EWMA/GARCH volatility, (e) Logistic Regression, (f) Random Forest, (g) XGBoost?
- **Secondary (RQ2):** Does adding causal HMM-filtered probabilities to the original BullBench next-close forecasters reduce MAE/RMSE versus the same forecaster without them?
- A negative result is a valid result and is reported in full.

## 2. Data and price basis
- Assets: HDFCBANK, ICICIBANK, TCS, RELIANCE, TATASTEEL, NIFTY 50 (NIFTY reported separately; it is an index, not an equity).
- Source: official NSE / NSE Indices exports only (see `DATA_SOURCES.md`). Yahoo data is legacy/exploratory and never mixed in.
- **Return definition (PROPOSED):** `r_t = ln(Close_t / PrevClose_t)` using the exchange-published previous-close field of the same file, so bonus/split ex-dates are not counted as price moves.
  - **Precondition:** verified on known ex-dates (HDFCBANK 2025-08-26, RELIANCE 2024-10-28, TATASTEEL split date TBD-verify) and recorded in `CORPORATE_ACTIONS.md`. If the field is not adjusted, fall back to an explicit documented adjustment-factor table. Never mix adjusted and unadjusted closes.
- **Sessions:** only completed regular sessions. Special/abbreviated sessions (Muhurat, weekend special sessions) carry `session_type != regular` and are excluded from **targets** (they may stay in raw data). Policy TBD in DECISIONS.
- No forward-fill, no interpolation, no synthetic rows. Rolling windows run over observed sessions only; gaps longer than TBD calendar days invalidate the window and the row is dropped and logged.

## 3. Target (primary)
- `y_{t+1} = 1` if `|r_{t+1}| > θ_a`, else 0, for asset *a*.
- **θ_a (PROPOSED):** one fixed value per asset = 80th percentile of `|r|` over the **first training block only**, not re-estimated per fold. Rationale: per-fold thresholds change the label between folds and make pooled metrics incomparable.
- Report per asset and per block: base rate in train, validation and test. A large prevalence shift is reported, not hidden.
- Label name in UI/docs: "large absolute price move". It is not realized volatility and not a hidden-state label.

## 4. Observation vector o_t (HMM input)
Candidates, chosen on validation held-out log-likelihood and calibration only:
- A: `[r_t]`
- B: `[r_t, ln(High_t / Low_t)]` (range-based volatility proxy from OHLC)
- Optional later: VIX level if its availability time is proven ≤ cutoff.
Scaling (robust or standard) is fit on training data only and serialized.

## 6. Models
**HMM (own NumPy implementation is the deliverable; `hmmlearn` is a test oracle only)**
- Gaussian emissions, states ∈ {2, 3, 4}, covariance ∈ {diag, full} (TBD subset), EM/Baum-Welch with ≥ TBD random restarts, fixed seeds, convergence tolerance and max iterations recorded, covariance floor recorded.
- Inference path uses **filtering only**. Smoothing and Viterbi are display-only and never feed a historical forecast.

**Baselines (same target, same dates)**
1. Training prevalence
2. Persistence of previous large-move label
3. Observable Markov chain on the binary label
4. EWMA volatility → P(|r| > θ) under a stated distribution
5. GARCH(1,1) with Student-t innovations → P(|r| > θ) (package `arch`)
6. Logistic Regression
7. Random Forest
8. XGBoost
Supervised models use one shared lagged feature set (lagged |r|, rolling vol 5/10/20/60, lagged return) built with `shift()`. Hyperparameter grids: TBD, small, fixed before freeze.

## 7. HMM event probability (causal)
With filter `α_t = P(z_t | o_1:t)` and transition matrix `A`:
```
π_{t+1|t} = α_t · A
P(|r_{t+1}| > θ | o_1:t) = Σ_j π_{t+1|t}(j) · [ 1 − Φ((θ − μ_j)/σ_j) + Φ((−θ − μ_j)/σ_j) ]
```
`μ_j, σ_j` are the return-dimension emission parameters of state *j* (marginal of the Gaussian), with θ transformed into the scaled space. If this mapping fails validation calibration, a two-stage model (state posterior → training-fit calibrator) is used and disclosed as such.

## 8. Calibration
Fit on training/validation only (method TBD: isotonic vs Platt, chosen on validation). Reliability curves always shown with bin counts.

## 9. Metrics and primary endpoint
- Per model, per asset: Brier score, log loss, PR-AUC, balanced accuracy and macro-F1 at a validation-chosen threshold, event count, base rate.
- **Primary endpoint (PROPOSED):** mean over the 5 equities of Brier skill score vs training prevalence. NIFTY 50 is secondary. All other metrics are descriptive.
- HMM likelihood diagnostics (held-out log-likelihood, restart stability, transition matrix, dwell times) are reported separately and are not compared with supervised metrics.

## 10. Inference
Paired circular block bootstrap on per-date loss differences (reuse `diagnostics.py`), block length 20 with 10 and 40 as sensitivity, ≥ 4,000 draws, seed fixed. Report pointwise and multiplicity-adjusted intervals. State that intervals are conditional on fitted predictions.

## 11. Secondary task (RQ2)
Original five forecasters, with and without filtered HMM features, identical splits and information sets. Metrics: close MAE/RMSE, skill vs previous close. On ex-dates the predicted close uses the documented adjustment factor.

## 12. Reporting obligations
Report convergence failures, rejected preprocessing, failed models and negative results. Save predictions per (asset, date, model); every metric must be reproducible from saved predictions. No number is hard-coded in the frontend.
